O primeiro projeto em vinte minutos

Do terminal vazio a um projeto versionado, ligado à API e pronto para um agente trabalhar nele.

A página do capítulo 1 funcionou sem build, mas não escala: sem JSX, sem TypeScript, sem pacotes, sem build de produção. Este capítulo monta o projeto de verdade.

Você precisa do Node 24 (ou 22.22+), Git, um editor e a extensão React Developer Tools. O Vite 8 aceita Node 20.19+, mas o React Router 8, que entra no capítulo 13, exige 22.22+; começar no 24 evita trocar de versão no meio do livro.

2.1Gerando o projeto

terminal
npm create vite@latest mini-prontuario-web \
  -- --template react-ts
cd mini-prontuario-web && npm install
npm run dev     # http://localhost:5173

O index.html é a única página: um <div id="root"> e o script de src/main.tsx, que cria a raiz do React. O vite.config.ts configura o Vite, os tsconfig*.json os tipos, e o .oxlintrc.json o linter, já com as regras dos Hooks.

Dado · o template de outubro de 2026

2.2Scripts e o portão

dev serve a tela e a atualiza quando você salva; build confere os tipos e gera dist/; preview serve o build; lint roda o oxlint. O projeto acrescenta gate, que roda tudo o que precisa passar antes de qualquer entrega:

terminal · Medido
{{SAIDA:c2-gate-curto.txt}}

O tsc -b não gera arquivos (o tsconfig tem noEmit): quem transforma TypeScript em JavaScript é o Vite, e ele não confere tipos. Por isso o dev mostra a tela mesmo com erro de tipo, e o gate não deixa esse erro passar.

2.3O ponto de entrada

{{BLOCO:cap02:src/main.tsx}}

createRoot liga o React a um nó do DOM, e render faz o primeiro desenho. StrictMode só age em desenvolvimento: chama cada componente duas vezes por render e monta e desmonta cada efeito uma vez a mais, para revelar código que depende de rodar uma vez só. Os capítulos 3 e 7 mostram o que ele pega.

2.4A tela e a API na mesma origem

A tela roda em :5173 e a API em :3000. Portas diferentes são origens diferentes para o navegador, o que traria CORS e regras de cookie entre sites. O proxy do Vite evita isso:

{{BLOCO:cap02:vite.config.ts}}

Em produção não há Vite: o build vira arquivos estáticos e o servidor que os publica faz o papel do proxy. O código não muda, porque nunca usa endereço de servidor:

Regra · UI-00

O front chama a API por caminho relativo (/api/...). Verificação: grep -rn "localhost:3000" src não encontra nada.

O App do template virou um verificador: um botão cujo handler de evento chama fetch("/health") e guarda o resultado em estado. Buscar dados ao abrir a tela pede useEffect, e há bons motivos para esperar até o capítulo 7. A sessão também passa pelo proxy: este roteiro entra como Ana pela tela e consulta quem está logado.

O cookie chegou HttpOnly, Secure e SameSite=Lax, o JavaScript da página não o lê, e mesmo assim o pedido seguinte saiu autenticado: o navegador anexa o cookie sozinho. O capítulo 15 constrói a sessão da tela sobre isso; o porquê de cada atributo está no Crachá & Porta, capítulo 5.

Para inspecionar, a extensão React Developer Tools acrescenta as abas Components (árvore, props e estado) e Profiler (quem renderizou e quanto levou). O Vite entrega source maps: os breakpoints param no .tsx original.

2.5Git e o contexto do agente

O primeiro commit vem antes da primeira feature, com quatro arquivos que o agente lê antes de qualquer tarefa:

ArquivoO que guarda
AGENTS.mdComandos, como o projeto funciona e regras; formato que Codex e agy leem
CLAUDE.mdUma linha, @AGENTS.md: o Claude Code importa o mesmo conteúdo
INVARIANTES.mdRegras com verificação; começa com a UI-00
IA.mdCada tarefa feita com agente: pedido, verificação, o que foi recusado
Ponte · Dev de IA, caps. 3 a 5

Por que o contexto deve ser curto e como um invariante ganha verificação executável: o mapa dos cinco arquivos (cap. 3), CLAUDE.md e AGENTS.md (cap. 4) e INVARIANTES.md (cap. 5).

Armadilha de IA

Diante de um erro de CORS, o agente costuma propor fetch("http://localhost:3000/...") e liberar origin: "*" na API. As duas mudanças funcionam e estão erradas: a primeira quebra a UI-00 e a produção, a segunda abre a API para qualquer site. O AGENTS.md já proíbe mexer na API e no Vite. Comandos de agente mudam rápido; confira na versão instalada.

Exercícios

  1. EssencialGere o projeto, configure o proxy e faça o botão mostrar ok. Pare a API e clique de novo: o que aparece, e por quê?
  2. IntermediárioIntroduza um erro de tipo no App.tsx. Rode npm run dev e depois npm run gate e explique a diferença.
  3. DesafioRode npm run build e npm run preview: o botão funciona. Descubra na documentação do Vite por quê, e escreva a configuração que um servidor de produção (nginx, por exemplo) precisaria para a UI-00 continuar valendo.
