Introdução

Para quem é este livro, a ideia que ele defende e como cada capítulo funciona.

Você já sabe fazer uma página reagir a um clique. Este livro trata do passo seguinte: fazer uma aplicação inteira continuar certa quando ela tiver trinta telas, várias pessoas no código e um agente de IA escrevendo boa parte dele.

É para quem já constrói páginas com HTML, CSS e JavaScript, manipula o DOM, consome uma API com fetch e já escreveu um backend REST com Express e TypeScript. Nada disso é ensinado de novo. Se você cursa TEC.1052, guarde por perto o front-end do Mini-Prontuário que escreveu em JavaScript puro: ele é o ponto de partida do capítulo 1.

A tela é uma função do estado. Quase todo bug de front-end é um estado guardado no lugar errado, duplicado ou sincronizado à mão.

Por isso o livro não é uma lista de APIs do React. Cada capítulo responde, de um ângulo diferente, a uma pergunta: onde este estado mora?

O laboratório

H+

O livro inteiro acontece num hospital

Ao lado de cada leito há um monitor. Ninguém redesenha a tela dele à mão: os sensores mudam um número e o monitor atualiza só a faixa que mudou. É o modelo mental do React, e o mundo de todas as analogias do livro.

O projeto é o cliente React do Mini-Prontuário, que conversa com a API do ebook Crachá & Porta: sessão em cookie, permissões por papel e uma suíte de ataques. A interface é nova; o servidor é real desde o primeiro dia. São três repositórios, estado-e-tela-api, estado-e-tela-web (uma tag git por capítulo) e estado-e-tela-ebook, com este livro, os roteiros de medição e as saídas. Todos os pacientes são fictícios.

Como cada capítulo funciona

A ordem é sempre a mesma: o problema num sintoma do Mini-Prontuário; o modelo mental, com a caixa Onde a analogia para; o mecanismo por dentro e na prática; o erro clássico e a prova, um teste que falha sem a correção; o trabalho com agentes de IA; e o fechamento, com exercícios em três níveis.

Este livro faz parte de uma série. O Desenvolvimento Dirigido por IA, o Dev de IA, ensina o método de trabalhar com agentes; aqui ele é aplicado ao React, sem repetição. Quando um procedimento está detalhado lá, uma caixa Ponte · Dev de IA resume e aponta o capítulo. Os prompts seguem os formatos da disciplina:

A régua e as convenções

O capítulo 20 lista 36 competências de um desenvolvedor sênior de front-end, cada uma com a evidência exigida. Marcar 27 com evidência é chegar a 75%. Cada capítulo diz quais itens entrega.

  • Dado é fato externo, com fonte. Medido é saída real de código que rodamos, guardada em saidas/; nenhuma foi escrita à mão.
  • Todo código impresso sai do git, na tag indicada na barra do bloco, em linhas de até 46 caracteres.
